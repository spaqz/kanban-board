# План тестирования (Test Plan)

## 1. Введение
**Объект тестирования:** REST API для Kanban-доски (аналог Jira).
**Цель:** Проверить работоспособность основных бизнес-сценариев (аутентификация, создание проектов, управление досками и карточками), а также проверить обработку ошибок и ограничений (WIP-лимиты).

## 2. Ресурсы
* **Инструменты:** Jest (юнит-тесты), Supertest (интеграционные тесты), Swagger (ручное API-тестирование).
* **Окружение:** Node.js 24, Windows 10/11, SQLite (тестовая БД).

## 3. Критерии начала и окончания
* **Начало:** Код собирается без ошибок TypeScript.
* **Окончание:** Все автоматические тесты (32 шт.) проходят успешно (PASS). Критических багов не найдено.

## 4. Стратегия тестирования
* **Юнит-тесты (Jest):** Проверка бизнес-логики сервисов (auth, project, board, card) с использованием моков (имитации базы данных).
* **Интеграционные тесты (Supertest):** Проверка реальных HTTP-запросов к API с использованием тестовой БД SQLite.

## 5. Тест-кейсы (Автоматизированные)

| ID | Название | Шаги | Ожидаемый результат | Приоритет |
|----|----------|------|--------------------|-----------|
| TC-01 | Регистрация пользователя | Отправить POST /api/auth/register с валидными данными | Код 201, пользователь создан в БД | High |
| TC-02 | Регистрация с занятым email | Отправить POST /api/auth/register с существующим email | Код 409, ошибка "Email уже занят" | High |
| TC-03 | Вход в систему | Отправить POST /api/auth/login с верными данными | Код 200, возвращается JWT токен | High |
| TC-04 | Доступ без токена | Отправить GET /api/projects без заголовка Authorization | Код 401, ошибка "Токен не предоставлен" | High |
| TC-05 | Создание карточки | Отправить POST /api/cards с валидными данными | Код 201, карточка создана | High |
| TC-06 | Создание карточки без названия | Отправить POST /api/cards с пустым title | Код 400, ошибка валидации | Medium |

| TC-08 | Удаление чужого проекта | Отправить DELETE /api/projects/:id от имени не владельца | Код 403 (Forbidden) | Medium |

## 6. Риски
* Нестабильность тестовой БД при параллельном запуске (решено через последовательный запуск).
* Изменение структуры БД без обновления миграций.
